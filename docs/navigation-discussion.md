# 모바일 내비게이션 설계

상태: 구현됨 — 2026-10-25. 하단 메뉴, 내부 구성, 기본 진입 화면과 재방문 동작을 코드에 반영했다. 브라우저/번들 검증과 실기기 검증은 아래 실행 기록을 구분한다.

## 합의한 방향 — 2026-10-24

- 브랜드·커뮤니티·공지의 발견성을 높인다. 모든 목적지를 어느 화면에서나 한 번에 여는 것은 필수 조건이 아니다.
- 하단 핵심 탭은 5개로 유지하고 관련 콘텐츠는 상단 보조 탭 등으로 묶는다.
- 위스키를 발견하는 경험을 입구로 삼고 예약·구매로 이어지게 한다.
- 운영 공지와 위스키 소식은 사용자 관점에서 구분한다. 용어는 [GLOSSARY](../GLOSSARY.md)를 따른다.

## 확정한 메뉴 그룹 — 2026-10-25

| 하단 메뉴 | 내부 구성 | 첫 진입 기본 화면 |
| --- | --- | --- |
| 홈 | 기존 홈 | 홈 |
| 아카이브 | 브랜드 / 아카이브 | 브랜드 |
| 스토어 | 예약 / 상품 | 예약 |
| 커뮤니티 | 공지 / 커뮤니티 / 소식 / 스토리 | 공지 |
| 마이 | 이용 내역·멤버십·계정 관리 | 마이페이지 |

홈을 탐색으로 바꾸거나 커뮤니티·소식을 홈 안에 넣는 이전 제안은 채택하지 않는다. 운영 공지의 주요 위치는 커뮤니티 안이다. 홈 공지 미리보기와 마이의 추가 공지 링크는 확정한 요구가 아니다.

사용자는 소식을 커뮤니티의 상단 탭에 유지하는 추천과 하위 스토어를 ‘상품’으로 표시하는 제안을 수락했다. 이후 사용자는 브랜드·예약·공지를 기본 진입 화면으로 지정했다. 기본 화면을 상단 탭의 첫 위치에 둔다.

## 변경 전 구조와 확인한 제약

- 네이티브 하단: 홈 / 아카이브 / 예약 / 쇼핑 / 마이.
- 브랜드·커뮤니티·소식은 현재 하단 탭 밖의 Stack 화면이다.
- 커뮤니티와 소식은 기존 게시판 화면의 상단 탭으로 연결된다.
- 공지는 커뮤니티·소식 각각의 고정 공지/공지 필터로 구현되어 있다. 독립된 운영 공지 메뉴는 없지만 기존 API 계약은 GLOBAL/BOARD 구분과 전체 공지 전용 목록·상세를 지원한다. 실제 운영 서버 응답은 미확인이다.
- SDK58 NativeTabs는 Android에서 최대 5개 탭을 지원한다. [공식 제약](https://docs.expo.dev/router/advanced/native-tabs/#known-limitations)

## 구현 계약

- 브랜드·커뮤니티·소식의 목록은 실제 하단 탭 안에 호스팅한다. 기존 Stack 경로로 링크만 바꾸는 방식은 하단 바 유지 요구를 만족하지 않는다.
- 같은 앱 실행 중 다른 하단 영역으로 이동했다 돌아오면 각 보조 탭의 선택·검색·스크롤을 보존한다. 앱을 새로 실행하면 위 기본 화면으로 시작한다. 기존 공개 경로의 직접 진입은 명시한 목적지를 우선하며 기본 탭으로 덮어쓰지 않는다. `/general-items`, `/ticket-products`, `/smart-order` 목록은 `/shop?channel=general|ticket|smart`로 연결해 하단 바를 유지한다.
- 공지의 GLOBAL/BOARD scope에 따라 상세 진입을 구분한다. 기존 게시판 공지 응답에도 GLOBAL이 포함될 수 있다.

## 복귀와 기존 기능

- 하위 화면에서 iOS 가장자리 스와이프·Android 시스템 뒤로가기는 실제 내비게이션 기록을 따라 직전 목록과 선택 상태로 복귀한다.
- 상품 안의 일반 상품·이용권·스마트오더와 주문·결제 기능을 유지한다.
- 기존 브랜드·아카이브·예약·게시판 공개 링크가 해당 하단 영역과 보조 탭으로 연결되도록 한다.
- 같은 하단 탭을 다시 누르는 것만으로 기본 보조 탭을 강제로 선택하지 않는다.

설계 결정의 근거는 [ADR-0001](adr/0001-mobile-navigation-groups.md)에 기록한다. 실행 검증 기록은 아래와 [E2E 인프라](e2e-infrastructure.md)를 따른다. 실제 iOS/Android 검증을 번들 생성이나 브라우저 통과로 대신하지 않는다.

## 코드 구조

- `(tabs)/(archive)`에서 `/brand`, `/archive`를 호스팅하며 기본은 `brand`다.
- `(tabs)/(store)`에서 `/reservation`, `/shop`을 호스팅하며 기본은 `reservation`이다.
- `(tabs)/(community)`에서 `/notices`, `/board/community`, `/board/news`, `/stories`를 호스팅하며 기본은 `notices`다.
- `SectionTabs`는 Expo Router headless tabs와 공식 TabSlot의 지연 마운트·비활성 화면 분리를 사용한다. 방문한 화면의 검색·선택·스크롤 상태는 유지한다. 네이티브 하단 바는 기존 NativeTabs를 유지하며 활성 탭 재선택에 의한 pop/스크롤 초기화를 비활성화한다.
- `/notices/[announcementId]`는 기존 상세 Stack에 추가하며 전체 공지 전용 상세 API를 사용한다.

## 검증 — 2026-10-25

- 전체 브라우저 회귀 269/269, 재시도 0. 등록된 라우트 준비 검사 64/64.
- 단위·계약 160/160. 타입검사·린트·변경 파일 포맷 검사 통과.
- iOS/Android/web 배포 번들 생성 및 fixture 정보 제외 검사 통과.
- 기본 진입, 검색·스크롤·상품 종류 보존, 기존 상품 주소 연결, 공지 오류/빈 결과/페이지네이션, GLOBAL/BOARD 상세와 뒤로가기를 확인했다. 새 상단·하단 메뉴를 시각 검토한 뒤 아카이브 기준 이미지만 갱신했다.
- 네이티브 기본 메뉴 시나리오를 추가했고 Maestro YAML 12개 형식 검사를 통과했다. Xcode·Maestro·Android SDK/adb가 없어 네이티브 실행은 하지 않았다. 브라우저 회귀는 실기기 제스처 검증이나 실제 운영 API 검증을 대신하지 않는다.

## 스토리 탭·상단 메뉴 검증 — 2026-10-25

- 커뮤니티에 `/stories` 목록을 포함하고 기존 상세 Stack과 URL을 유지했다. 기본 공지·하단 5개 영역은 유지한다.
- 320/390/430px와 가로 844px에서 4개 탭 노출·최소 터치 크기, 상세 진입/뒤로가기, 검색어 보존, 키보드 Enter 선택, 하단 영역 재방문을 검사했다. 차콜·Navi Sans를 유지하며 왼쪽 정렬·일관된 여백·3px 선택 표시로 정돈했다.
- 전체 브라우저 회귀 275/275, 재시도 0. 라우트 준비 검사 66/66. 단위·계약 165/165. 린트·타입검사·변경 파일 포맷 검사 통과.
- iOS/Android/web 배포 번들 생성과 fixture 정보 제외 검사 통과. Maestro 12개 YAML 형식 검사 통과. simctl/adb가 없어 이번 작업의 실제 네이티브 실행은 하지 않았다. 브라우저 캡처는 실기기 검증을 대신하지 않는다.
