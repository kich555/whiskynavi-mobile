# 모바일 내비게이션 논의

상태: 논의 중. 메뉴 배치와 구현 범위는 아직 확정하지 않았으며 앱 코드를 변경하지 않는다.

## 합의한 방향 — 2026-10-24

- 브랜드·커뮤니티·공지의 발견성을 높인다. 모든 목적지를 어느 화면에서나 한 번에 여는 것은 필수 조건이 아니다.
- 하단 핵심 탭은 5개로 유지하고 관련 콘텐츠는 상단 보조 탭 등으로 묶는다.
- 위스키를 발견하는 경험을 입구로 삼고 예약·구매로 이어지게 한다.
- 운영 공지와 위스키 소식은 사용자 관점에서 구분한다. 용어는 [GLOSSARY](../GLOSSARY.md)를 따른다.

사용자는 첫 라운드의 추천 방향을 수락했다. 아래 구성안과 미결정 항목을 수락한 것으로 확대 해석하지 않는다.

## 확인한 현재 구조

- 네이티브 하단: 홈 / 아카이브 / 예약 / 쇼핑 / 마이.
- 브랜드·커뮤니티·소식은 현재 하단 탭 밖의 Stack 화면이다.
- 커뮤니티와 소식은 기존 게시판 화면의 상단 탭으로 연결된다.
- 공지는 커뮤니티·소식 각각의 고정 공지/공지 필터로 구현되어 있다. 독립된 운영 공지 메뉴는 없지만 기존 API 계약은 GLOBAL/BOARD 구분과 전체 공지 전용 목록·상세를 지원한다. 실제 운영 서버 응답은 미확인이다.
- SDK58 NativeTabs는 Android에서 최대 5개 탭을 지원한다. [공식 제약](https://docs.expo.dev/router/advanced/native-tabs/#known-limitations)

## 다음 라운드 제안 — 미확정

기존 하단 5개를 유지하고 홈 상단에 추천 / 커뮤니티 / 소식, 아카이브 상단에 위스키 / 브랜드를 배치하는 안을 우선 비교한다. 이 안은 예약·쇼핑의 접근성을 유지하며 기존 햄버거 메뉴에 의존하던 콘텐츠를 눈에 보이는 진입점으로 옮긴다.

운영 공지는 홈에 최신 공지 한 줄과 전체 보기, 마이의 고객 지원에 전체 공지 진입점을 두는 안을 제안한다. 아직 사용자 결정 전이다. ‘추천’은 기존 홈 콘텐츠를 뜻하며 새 개인화 추천 시스템을 의미하지 않는다.

## 구현 시 확인할 계약

- 브랜드·커뮤니티·소식의 목록은 실제 하단 탭 안에 호스팅한다. 기존 Stack 경로로 링크만 바꾸는 방식은 하단 바 유지 요구를 만족하지 않는다.
- 각 보조 탭의 선택·검색·스크롤을 화면 이동 후에도 보존하고 기존 공개 경로의 직접 진입을 유지한다. 정확한 기본 진입·재선택 동작은 최종 구조에 맞춰 확정한다.
- 공지의 GLOBAL/BOARD scope에 따라 상세 진입을 구분한다. 기존 게시판 공지 응답에도 GLOBAL이 포함될 수 있다.

## 미결정

- 하단 5개 항목의 실제 구성과 커뮤니티의 독립 하단 탭 필요 여부.
- 상단 보조 탭의 구체적인 배치·라벨·노출 범위.
- 운영 공지의 진입점과 기존 게시판/API 활용 범위.
- 탭 상태 보존, 기존 링크 및 뒤로가기 계약.

최종 합의가 확인되면 확정 설계를 기록하고 구현한다. ADR은 실제로 유지 비용이 큰 선택과 대안·트레이드오프가 확정되는 경우에만 작성한다.
