# 모바일 로딩·마이페이지 화면 계약

## 처음 불러오기와 새로고침

처음 불러오는 데이터가 없을 때만 화면 구조에 맞는 스켈레톤을 표시한다. TanStack Query의 최초 fetch 상태와 데이터 유무를 사용하며, 이미 읽은 본문·행·입력 내용을 백그라운드 갱신 때문에 제거하지 않는다. 다음 페이지를 읽을 때는 기존 행 아래에 작은 스켈레톤을 추가한다. 빈 결과와 오류는 로딩 상태가 끝난 뒤 구분하며, 장바구니는 조회 중이나 오류일 때 빈 장바구니 문구를 표시하지 않는다.

실제 데이터 요청이 없는 화면에 인위적인 지연을 넣지 않는다. 모든 진입 화면은 글꼴 준비 스켈레톤의 적용을 받고, 보호 화면은 세션 복원을 기다리는 동안 폼/계정 스켈레톤을 표시한다. 글꼴 실패·지연 시 기존 기본 글꼴 계속하기 동작을 유지한다. 로그인·저장·주문 승인 같은 사용자 작업은 기존 버튼의 진행 상태와 중복 실행 방지를 유지한다.

## 동작과 접근성

`src/components/native/skeleton.tsx`는 cards/rows/detail/article/form/account/hero/media/inline/app의 명시적 구조를 제공한다. 그리드는 화면의 실제 1/2열 전환에 맞춘다. 도형은 스크린리더에서 숨기고 바깥 영역만 이름이 있는 indeterminate progressbar/busy 상태로 노출한다. 입력이나 링크를 포함하지 않으며 터치를 가로채지 않는다.

차콜 표면 위의 중립색 도형에 opacity만 변화시키는 맥동을 적용한다. 네이티브 드라이버와 isInteraction=false를 사용하고, 모션 줄이기·앱 비활성 상태에서는 애니메이션을 멈춘다. 최초 접근성 설정 확인 전과 조회 실패 시에는 정지 상태다. 화면에서 사라질 때 애니메이션과 이벤트 구독을 정리한다. 이미지와 카드 공간은 원래 비율을 예약한다.

## 마이페이지 하위 화면

주문·예약·문의 목록은 상태 배지 → 제목 → 금액/수량 또는 픽업/대화 정보 순서의 전체 카드 링크다. 주문 상세는 주문 정보/결제/입금 안내/배송·수령/이용권/주문 관리로 나눈다. 취소·수령·이용권 사용은 기존 서버 API, 허용 상태, 확인 절차를 유지한다.

멤버십은 실제 계정의 NAVI/TALES 가입 상태와 기존 혜택 안내를 나누고, 실행되지 않는 가입 버튼이나 가상의 등급·잔액을 추가하지 않는다. 내 정보는 닉네임·이메일·비밀번호·수신 동의의 독립 패널이다. 사업자는 정보/증빙 서류/진행 현황으로 구분하고, FAQ는 펼침 상태를 알리는 질문 행으로 표시한다.

마이페이지의 주문·예약·내 정보·멤버십·사업자 등록·FAQ는 각각 `/my-page/{section}` 독립 라우트이며 기존 이용권·문의 라우트와 같은 네이티브 Stack에 push한다. iOS 기본 뒤로가기 제스처를 활성화하고 Android 시스템 뒤로가기는 Stack의 pop을 따른다. 네이티브에는 기본 헤더의 뒤로가기를 사용하고 웹에서는 마이페이지 복귀 버튼을 유지한다. 반복되는 전체 메뉴는 제거했다. 기존 `?tab=...` 링크는 먼저 overview의 검색 파라미터를 지운 후 독립 화면을 push해, 뒤로가기 시 하위 화면이 다시 열리지 않도록 한다. 상세의 목록 복귀 링크는 dismissTo로 기존 목록까지 돌아가며 같은 목록을 중복해서 쌓지 않는다. 예약 이력 상세는 연결된 공고이며 현재 API가 제공하지 않는 개별 신청 정보를 상세에 만들어 표시하지 않는다.

## 검증 범위

Playwright는 로컬 합성 API 응답을 보류·해제해 23개 화면의 로딩→내용 전환을 검사한다. busy 상태·비상호작용 도형·잘못된 빈 결과 숨김, 모션 줄이기, 오류/재시도, 추가 페이지에서 기존 카드 보존, 장바구니 갱신 중 기존 행 보존, 원격 이미지 성공·실패를 검사한다. 마이페이지 하위 12화면을 320/390/430px 및 844px 가로 화면에서 확인한다. 캡처는 artifacts/skeleton-_.png와 artifacts/account-_-390.png/430.png에 저장한다.

이는 RN 웹 미리보기 검증이다. WebView/NICE 완료·iOS/Android 세션 복원·실기기 화면은 JS 번들 및 소스 연결 확인과 실제 런타임 검증을 구분해야 한다. Maestro 10개 flow 중 10-account-child-pages.yaml은 주문/예약/멤버십/정보 수정 딥링크를 확인하도록 구성했으며, YAML 검사 통과는 네이티브 실행 통과가 아니다.
