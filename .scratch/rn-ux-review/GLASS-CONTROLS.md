# 공통 컨트롤의 Glassmorphism 개선

2026-10-18 · 기준 `1dc5e9b` 이후 사용자가 기본 버튼·체크박스의 세련된 디자인과 Glassmorphism을 요청해 적용했다. 웹 원본의 로고·차콜 배경·상품 콘텐츠는 유지한다.

## 시각 기준

`ui-ux-pro-max`의 Glassmorphism 스타일 및 React Native 접근성·터치 지침을 사용했다. 차콜 표면 위에 옅은 흰색 반사와 얇은 밝은 테두리를 놓고, 밝은 진주색을 주요 행동에 사용한다. 색상·모서리·표면·포커스를 공통 material 토큰으로 관리한다.

- 주요 버튼: 진주색 표면, 상단 빛 반사, 16px 연속 곡면, 낮은 그림자. 보조 버튼은 어두운 반투명 표면과 가는 테두리를 사용한다.
- 필터 체크박스: 56 단위 이상의 행 전체가 선택 영역이다. 체크 표시·선택된 행의 색·테두리로 상태를 중복 전달한다. 회원가입·주문 동의에도 같은 컴포넌트를 적용했다.
- 입력창: 16px 곡면, 부드러운 배경, 작은 필드 라벨, 오류 테두리와 별도 오류 설명. 포커스 때 밝은 테두리와 약한 외곽 강조가 나타난다. 입력의 기본 웹 외곽선은 이 대체 표시를 제공하면서 제거한다.
- 필터 칩·검색·정렬·헤더 아이콘도 같은 모서리와 표면을 사용한다. 상품 상세 버튼은 기존 대비를 보장하는 앰버 색을 유지하며 곡면과 테두리만 정리했다.
- 시트는 바깥 여백 8, 곡면 28, 어두운 유리 표면으로 분리했다. 아래의 `필터 초기화`와 밝은 `결과 보기`를 구분한다. 상단 완료·바깥 닫기·Escape·Android Back 계약은 유지한다.

## 플랫폼과 성능

기존에 설치되어 있던 `expo-glass-effect`와 `expo-linear-gradient`를 사용한다. 새 의존성이나 native 디렉토리를 추가하지 않았다.

- iOS: `isGlassEffectAPIAvailable()`와 `isLiquidGlassAvailable()`가 모두 참이며 투명도 줄이기가 꺼진 경우에만 `GlassView`를 표시한다. 실행 중 설정 변경을 구독하고 해제한다.
- Android 및 지원되지 않는 iOS: 불투명한 차콜 표면과 빛 반사로 같은 형태를 제공한다. 이 경로가 실제 배경 블러인 것으로 주장하지 않는다.
- 웹: 브라우저 배경 블러를 사용하며 `prefers-reduced-transparency`가 켜지면 불투명 표면으로 바꾼다.
- 비싼 배경 샘플링은 떠 있는 시트에만 둔다. 목록의 체크박스·버튼은 단순 반사를 사용한다. 새 자동 애니메이션이나 위치를 흔드는 누름 효과를 추가하지 않았다.

공식 API 근거: [Expo SDK 57 GlassEffect](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/), [React Native 0.86 스타일](https://reactnative.dev/docs/0.86/view-style-props).

## 검증

린트·타입·포맷과 단위/계약 테스트 102개를 통과했다. 최종 Playwright 37개가 갱신 옵션 없이 통과했다. 기존 35개 여정에 아래를 추가했다.

1. 주문서에서 동의 체크박스를 Space로 선택/해제하고 기존 필수 입력 검증과 조작 크기를 확인한다. RN Web 0.21은 checkbox 역할의 Space를 자동 처리하지 않아 웹에서만 명시적으로 지원했다. Enter는 기존 Pressable 동작을 유지한다.
2. 시트 전환·포커스 초기화 후 선택된 유리 체크박스의 시각 회귀를 비교한다. 아카이브·로그인 기준도 직접 화면을 검토한 뒤 갱신했고 소개 기준은 유지했다.

동일한 개발 API의 웹/RN 조회 전용 비교에서 캡처 19개, 페이지 오류 0, 변경 요청 0을 확인했다. `rn-archive-filter-selected.png`가 추가된 실제 RN 웹 미리보기 캡처다. AI 예상 시안이 아니다.

실제 iOS Liquid Glass, VoiceOver/TalkBack, 기기 투명도 설정·성능은 실행 도구 부재로 미검증이다. 이전 티켓 07의 cold-start 측정·리소스 최적화와 티켓 13의 native 검증은 계속 남아 있다. 웹 미리보기 통과를 native 기기 E2E 통과로 해석하지 않는다.

최종 iOS·Android·웹 Expo export와 운영 번들의 fixture 혼입 검사도 통과했다. 이는 AAB/IPA 설치나 기기 실행 통과가 아니다. 웹 문서 완료 검사도 영향 페이지 없음·136개 동기화 통과를 확인했다.
