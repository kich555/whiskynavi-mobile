# 07: 첫 실행에서 빈 화면 없이 탐색 시작하기

**What to build:** 글꼴·기본 이미지가 느리거나 실패해도 사용자는 시작 상태를 알 수 있고 홈과 보틀 탐색을 시작할 수 있다.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Priority:** medium

**Finding:** M03

**Spec:** S03

- [ ] 현재 글꼴·이미지 크기와 같은 기기의 최소 5회 cold-start 표본을 먼저 기록한다.
- [ ] 글꼴 대기·실패 시 빈 화면이 계속 남지 않으며 명확한 시작 상태나 사용 가능한 대체 화면을 제공한다.
- [ ] 필수 리소스 최적화는 한글·라틴·숫자·브랜드 글리프와 폰트 라이선스를 보존한다.
- [ ] 동일 조건 전후 중앙값·표본·첫 콘텐츠/조작 가능 시점을 구분하고 실제 개선 없는 수치를 꾸미지 않는다.
- [ ] 시작→홈→아카이브→보틀 상세가 정상·글꼴 지연·오류에서 동작하고 기존 시각 기준을 검토한다.

**Verification boundary:** 기존 사용자 조작→fixture API→표시 결과의 여정을 사용한다. 스키마·API 변경이 필요 없는 티켓에 가상의 백엔드 작업을 추가하지 않는다. 실제 실행한 검증만 완료 증거로 남긴다.
