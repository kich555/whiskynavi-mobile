# 13: 개선된 흐름을 실제 네이티브 환경에서 검증하기

**What to build:** 개선된 탐색·읽기·로그인 흐름이 iOS와 Android에서 실제 동작하는지 결과와 미검증 범위를 프로젝트 운영자가 확인할 수 있다.

**Blocked by:** 01: 메뉴를 선택한 순간에만 닫고 이동하기, 02: 필터·정렬 시트의 읽기와 복귀를 보장하기, 03: 헤더·칩·배너를 실수 없이 누르기, 04: 상품의 상세 버튼과 판매 상태를 또렷하게 읽기, 05: 큰 글자로도 보틀과 상품을 비교하기, 06: 홈 배너를 원하는 속도로 읽기, 07: 첫 실행에서 빈 화면 없이 탐색 시작하기, 08: 홈에서 실패한 콘텐츠만 다시 불러오기, 09: 로그인 입력 오류를 잃지 않고 교정하기, 10: 스와이프 없이도 보틀의 모든 이미지 보기.

**Status:** ready-for-agent

**Priority:** medium

**Finding:** M07

**Spec:** S03

- [ ] 기존 Maestro 6개·메모리 fixture·실행 스크립트·CI 정의를 재사용하고 운영 API 차단을 유지한다.
- [ ] iOS/Android 각각 기기 또는 에뮬레이터, OS·빌드 변형·커밋·실행 명령·시나리오별 결과를 기록한다.
- [ ] 시트·시스템 Back·키보드·글자 확대·갤러리·로그인 복귀를 native runtime에서 확인한다.
- [ ] VoiceOver/TalkBack 수동 검수는 실제 수행한 내용과 관찰 결과를 기록한다.
- [ ] 웹 E2E·타입·린트·번들 검사와 네이티브 통과를 구분한다. 도구나 원격 CI가 준비되지 않으면 해당 항목은 미실행으로 남기고 완료로 처리하지 않는다.
- [ ] 실결제·NICE 인증 완료·실메일 발송이나 운영 데이터 변경 없이 검증한다.

**Verification boundary:** 기존 사용자 조작→fixture API→표시 결과의 여정을 사용한다. 스키마·API 변경이 필요 없는 티켓에 가상의 백엔드 작업을 추가하지 않는다. 실제 실행한 검증만 완료 증거로 남긴다.
