# 09: 로그인 입력 오류를 잃지 않고 교정하기

**What to build:** 사용자는 비밀번호를 확인하고 잘못된 입력이나 네트워크 실패를 이해한 뒤 입력을 잃지 않고 로그인 또는 이메일 복구를 이어간다.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Priority:** medium

**Finding:** M05

**Spec:** S02

- [ ] 비밀번호 표시/숨김을 상태와 이름으로 안내하고 원문이 로그나 오류 내용으로 유출되지 않는다.
- [ ] 필드별 오류·도움말이 해당 입력과 연결되고 제출 실패 때 적절한 안내/포커스로 이동한다.
- [ ] 키보드 다음/제출·자동완성·붙여넣기와 중복 요청 방지를 보존한다.
- [ ] 잘못된 이메일·잘못된 비밀번호·통신 실패 후 입력을 보존하고 성공 시 허용된 복귀 경로로 이동한다.
- [ ] 이메일 복구 흐름은 합성 fixture로만 검증하며 실제 메일 발송·실제 계정 암호 변경을 수행하지 않는다.

**Verification boundary:** 기존 사용자 조작→fixture API→표시 결과의 여정을 사용한다. 스키마·API 변경이 필요 없는 티켓에 가상의 백엔드 작업을 추가하지 않는다. 실제 실행한 검증만 완료 증거로 남긴다.
