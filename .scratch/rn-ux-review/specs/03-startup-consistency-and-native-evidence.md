# S03: 첫 화면 신뢰도와 실제 네이티브 완료 증거

**Status:** ready-for-agent

**Review baseline:** `b0d740939d9c37d6ba20b58a55ebcd08e7bcdc4d`

## Problem Statement

현재 앱은 큰 글꼴 리소스 로딩을 기다리는 동안 빈 루트를 반환하며, 기존 검증은 웹 미리보기 위주다. 사용자는 기기에서 실제로 얼마나 빨리 보이고 읽기·터치·뒤로가기가 제대로 작동하는지 확인된 결과가 필요하다.

## Solution

브랜드 글리프와 이미지를 보존하면서 첫 화면을 안정적으로 제공하고, 보틀 탐색의 기준이 흩어지지 않게 관리하며, 실제 네이티브 사용자 여정의 증거를 남긴다.

## User Stories

1. As a 앱 사용자, I want 첫 실행에서 빈 화면 대신 안정된 시작 화면을 보는 것, so that 앱이 실행되고 있음을 안다.
2. As a 앱 사용자, I want 필수 글꼴이 늦어져도 탐색 시작을 이해할 수 있는 것, so that 앱이 멈췄다고 오해하지 않는다.
3. As a 한국어 사용자, I want 최적화 뒤에도 한글·숫자·브랜드명이 정확히 보이는 것, so that 상품을 혼동하지 않는다.
4. As a 앱 사용자, I want 글꼴 실패에서도 앱을 사용할 수 있는 것, so that 일시적인 리소스 문제로 탐색이 막히지 않는다.
5. As a 개발자, I want 동일 기기의 cold-start 전후 측정치를 보는 것, so that 근거를 갖고 로딩을 개선할 수 있다.
6. As a 보틀 사용자, I want 목록과 상세의 글자·간격·상태 의미가 일관적인 것, so that 같은 제품을 자연스럽게 비교할 수 있다.
7. As a 기존 웹 사용자, I want 앱의 로고와 사진·기본 분위기가 유지되는 것, so that 브랜드의 연속성을 느낀다.
8. As a iOS 사용자, I want 기기에서 뒤로가기·시트·글자 확대가 검증되는 것, so that 일상적인 탐색을 완료할 수 있다.
9. As a Android 사용자, I want 시스템 Back·키보드·하단 인셋이 검증되는 것, so that 실제 기기에서 조작할 수 있다.
10. As a 화면낭독기 사용자, I want 실제 VoiceOver/TalkBack 여정이 검수되는 것, so that 추측한 접근성에 의존하지 않는다.
11. As a 프로젝트 운영자, I want 로컬과 CI의 실행·실패·미실행 범위를 구분하는 것, so that 배포 준비 상태를 판단할 수 있다.
12. As a 개발자, I want 기존 테스트 계정·fixture·러너를 재사용하는 것, so that 검증 체계가 중복되지 않는다.
13. As a 프로젝트 운영자, I want 외부 API를 차단한 상태로 회귀를 실행하는 것, so that 운영 데이터에 테스트가 섞이지 않는다.
14. As a 작업자, I want 선행 티켓이 완료된 작업부터 실행하는 것, so that 불필요한 충돌과 재작업을 줄일 수 있다.

## Implementation Decisions

- M03·M07·L02를 다룬다. 측정 전에는 임의의 cold-start 숫자나 메모리 개선율을 목표 사실로 쓰지 않는다.
- 시작 화면/글꼴 실패 대체/필수 리소스 로딩을 한 사용자 시작 여정으로 정한다. 서브셋·형식 변경 등은 측정 후 선택하고 한글·라틴·숫자·상표 표기와 원본 라이선스를 유지한다.
- 아카이브 목록→상세의 의미 있는 시각 값을 국소적으로 통합한다. 전역 토큰 대개편을 다른 개선의 강제 선행 조건으로 만들지 않는다.
- 현재 웹·네이티브 테스트 러너, 메모리 fixture, Maestro 흐름, CI 작업을 확장한다. 새 병렬 러너나 운영 계정 복제 체계를 만들지 않는다.
- iOS와 Android의 정상 글자/확대 글자, 키보드, 시트, 뒤로가기, 이미지 이동, 로그인 복귀를 실제 native runtime에서 확인한다.
- 기기·OS·빌드 변형·커밋·실행 명령·scenario·결과·미실행 이유를 함께 기록한다. 에뮬레이터·실기기와 웹 결과를 혼합하지 않는다.
- 완료 증거 수집은 주요 사용자 여정 개선 뒤에 수행한다. 미실행은 통과로 변환하지 않고 해당 환경 준비를 후속 작업으로 남긴다. 원격 저장소와 CI 권한은 실제 연결 후 사용한다.

## Testing Decisions

- 시작→홈 표시→보틀 목록→상세의 기존 여정을 측정·검증 경계로 사용한다. 텍스트 렌더 전 내부 hook 호출 수 등 구현 상세는 검증하지 않는다.
- 동일 기기·동일 빌드 조건에서 최소 5회의 cold-start 전후 표본과 중앙값을 기록한다. 시간은 첫 의미 있는 콘텐츠/조작 가능 시점을 구분하고 실패 표본을 숨기지 않는다.
- 폰트 지연·오류 시나리오에서 빈 화면 지속 여부와 탐색 가능 여부를 확인한다. 로컬 파일 크기를 실제 다운로드량·메모리 사용량으로 오해하지 않는다.
- 보틀 흐름의 국소 스타일 정리는 기존 화면 회귀 기준과 상태/경계 검증으로 보장한다. 외관 변경이 없다면 기준 이미지의 의미 없는 갱신은 하지 않는다.
- 네이티브 검증은 기존 Maestro 흐름을 실행하고 VoiceOver/TalkBack·확대 글자 검수는 수동 증거도 허용한다. 자동화할 수 없는 항목의 실제 수행 사실을 분리한다.
- 기존 21개 웹 E2E·도메인 테스트·번들 검사를 유지한다. native 완료 여부는 웹 통과와 분리하고, 외부 요청 차단을 제거해 테스트를 통과시키지 않는다.

## Out of Scope

- 앱스토어 제출·프로덕션 배포·서명키 신규 발급
- 인증/결제/외부 제공자 서버의 정책 변경
- 지원하지 않던 태블릿/가로 방향을 새로 지원하는 것
- 확인하지 않은 성능 개선율·실기기 통과 수치 기재

## Further Notes

Ticket 07·12·13에 대응한다. 현재 로컬 도구와 실제 native runtime 가용성은 실행 전에 확인한다. 이 스펙 작성은 해당 검증의 실행 완료를 뜻하지 않는다.
