# S01: 누구나 탐색하고 읽을 수 있는 모바일 기본 조작

**Status:** ready-for-agent

**Review baseline:** `b0d740939d9c37d6ba20b58a55ebcd08e7bcdc4d`

## Problem Statement

사용자는 메뉴를 정확히 선택하고 필터·정렬을 읽고 닫을 수 있어야 하지만, 현재 메뉴 활성화·작은 터치 영역·활성 글자 대비가 그 경험을 방해한다. 글자 확대와 네이티브 시트의 접근성은 아직 증거가 부족하다.

## Solution

기존 웹 브랜드를 유지하면서 메뉴·시트·핵심 탐색·상품 상태를 안정적으로 조작하고 읽을 수 있게 한다. 변경은 사용자 행동의 결과로 검증한다.

## User Stories

1. As a 메뉴 사용자, I want 메뉴 안에서 스크롤해도 메뉴가 유지되는 것, so that 원하는 항목을 찾을 수 있다.
2. As a 키보드 사용자, I want Enter로 메뉴 항목을 선택하면 메뉴가 닫히는 것, so that 터치와 같은 경로로 이동할 수 있다.
3. As a 메뉴 사용자, I want 현재 페이지 항목을 다시 선택해도 메뉴가 닫히는 것, so that 페이지에 바로 돌아올 수 있다.
4. As a 화면낭독기 사용자, I want 시트를 열 때 제목과 문맥을 안내받는 것, so that 새 작업의 목적을 이해할 수 있다.
5. As a 화면낭독기 사용자, I want 시트가 열려 있는 동안 배경 화면이 읽기 순서에서 분리되는 것, so that 현재 작업에 집중할 수 있다.
6. As a 필터 사용자, I want 시트를 닫으면 원래 조작으로 돌아오는 것, so that 탐색 위치를 잃지 않는다.
7. As a Android 사용자, I want 시스템 뒤로가기로 현재 시트를 닫는 것, so that 예측 가능한 방식으로 작업을 종료할 수 있다.
8. As a iPhone 사용자, I want 충분한 유효 터치 영역으로 메뉴와 칩을 누르는 것, so that 정밀한 손동작 없이 탐색할 수 있다.
9. As a Android 사용자, I want 48dp 유효 영역에서 핵심 컨트롤을 누르는 것, so that 오작동을 줄일 수 있다.
10. As a 저시력 사용자, I want 상품 상세 버튼과 판매 상태를 충분한 대비로 읽는 것, so that 상품을 정확히 판단할 수 있다.
11. As a 색각 차이가 있는 사용자, I want 판매중·품절 텍스트를 색상과 함께 읽는 것, so that 색에만 의존하지 않는다.
12. As a 큰 글자 사용자, I want 확대한 글자에서도 보틀명과 필수 가격을 읽는 것, so that 정보를 비교할 수 있다.
13. As a 큰 글자 사용자, I want 필요하면 목록이 덜 촘촘하게 바뀌는 것, so that 조작이 잘리지 않는다.
14. As a 로그인 사용자, I want 키보드가 열려도 활성 필드와 다음 조작이 보이는 것, so that 입력을 완료할 수 있다.
15. As a 기존 사용자, I want 원래 로고·배경·상품 이미지를 유지하는 것, so that 웹과 같은 서비스를 알아볼 수 있다.

## Implementation Decisions

- H01~H04와 M01을 다룬다. 메뉴는 내용 전체의 touch-end가 아니라 항목의 활성화 완료를 닫힘의 근거로 삼는다. 백엔드·인증 계약은 바꾸지 않는다.
- 공유 시트의 네이티브 기본 동작을 먼저 확인한다. 기본 Modal이 이미 충족하는 포커스 처리를 중복 구현하지 않고, 실패가 관찰된 계약만 명시적으로 보강한다.
- 시트 제목·읽기 범위·닫기·포커스 복귀를 플랫폼별 사용자 행동으로 정의한다. Escape는 미리보기/하드웨어 키보드 경로, Android Back은 네이티브 경로로 구분한다.
- 유효 터치 영역은 iOS 최소 44pt, Android 최소 48dp를 목표로 한다. 시각 영역을 보존할 경우 추가 터치 영역이 이웃 컨트롤과 겹치지 않아야 한다.
- 일반 활성 글자는 대비 4.5:1 이상을 수용 기준으로 삼는다. amber/green 의미는 보존하되 기존 웹 색상을 이유로 낮은 대비를 고정하지 않는다.
- 시스템 글자 확대를 유지한다. 주 본문·메타데이터 역할을 분리하고, 필수 내용이 줄임표로만 남으면 상세 경로 또는 확장된 배치로 제공한다.
- 기존 Expo Router와 네이티브 탭을 유지한다. 전역 대규모 리팩터링을 선행 조건으로 만들지 않고 각 흐름을 독립적으로 개선한다.

## Testing Decisions

- 테스트 경계는 기존 사용자 여정 하나다: 메뉴 열기→항목 활성화→페이지, 필터 열기→변경→목록, 상품 상태 읽기→상세 진입을 UI와 API 결과로 관찰한다.
- 기존 Playwright·메모리 fixture·외부 요청 차단·Maestro 시나리오를 확장한다. 별도 러너를 추가하거나 컴포넌트 내부 props만 검사하는 테스트로 대체하지 않는다.
- 메뉴 스크롤 후 열림 유지, 현재 항목 Enter 선택 후 닫힘, 이동 1회, 시트 취소/뒤로가기 후 상태 보존을 회귀 검증한다.
- 활성 컨트롤의 유효 터치 영역과 간격, 글자/배경 대비를 실제 노출 상태에서 검사한다. 색상 literal 존재 여부만으로 통과시키지 않는다.
- 320·390·430 논리 폭과 글자 배율 1.0·1.6·2.0에서 필수 정보·버튼·키보드 노출을 검증한다. 네이티브 글자 확대와 VoiceOver/TalkBack은 웹 결과로 대체하지 않는다.
- 시각 기준은 현행 웹과 native 특성을 함께 사용한다. 의도한 접근성 보정은 이유와 비교 캡처를 남긴 뒤 기준을 갱신한다.

## Out of Scope

- 신규 로그인 정책, API 스키마나 결제 계약 변경
- 브랜드 재설계, 라이트 테마, 태블릿·가로모드 지원 확장
- 접근성 속성을 추가했다는 이유만으로 실기기 검증을 생략하는 것

## Further Notes

Ticket 01~05에 대응한다. 사용자에게 테스트 경계 확인을 다시 요청하지 않는 결정은 기존의 질문·승인 없이 진행하라는 위임을 따른다. 로컬 ready-for-agent 티켓으로 관리한다.
